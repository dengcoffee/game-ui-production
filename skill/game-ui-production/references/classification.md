# UI 分类判定与证据传递

分类以功能职责为主，结合本次原图、功能说明、布局/绑定及其他状态；外形、颜色和文件名只能辅助。识别由 Codex 完成，脚本检查分类记录与传递一致性，不声称已实现图像语义分类模型。

## 13 类判定表

| 分类 | ui_type | 判定依据与边界 |
|---|---|---|
| 底板 | base | 连续底色/底纹，承载窗口或面板内容；不把按钮内部填充当底板拆走 |
| 窗口框 | frame | 围成窗口边界；内部内容独立；按钮外框和头像框不因有框线归入本类 |
| 按钮 | button | 点击执行操作；默认保留填充、边框、固定装饰和效果，文字独立 |
| 页签 | tab | 切换内容分组/页面/模式，有同组与选中关系；只凭扁平矩形不能区分按钮 |
| 头像框 | avatar_frame | 包围头像显示区，不含头像本体；区域内的人物像素不提取进框 |
| 道具格 | item_slot | 容纳物品/装备的槽位，不含道具图像；按内容绑定判断，不凭方形轮廓 |
| 轨道 | scroll_track | 提供滑块移动路径的线/槽，包括滚动条和调节条；固定刻度可随轨道 |
| 滑块 | scroll_thumb | 在轨道上改变位置的柄；数值条端部装饰不因突出就算滑块 |
| 进度槽 | progress_track | 承载数值填充的固定槽底/外框；不因长条外形就认定为滚动轨道 |
| 进度填充 | progress_fill | 随数值变化裁切或伸展的内部填充；不是滑块移动柄或固定底纹 |
| 装饰 | decoration | 独立角饰、分隔线、纹样及光效等；附着于完整控件且无独立复用/行为时随控件 |
| 图标 | ui_icon | 表达功能或状态的图形，如关闭、设置、警告；人物/道具内容图仍遵守生产范围 |
| 字体 | font | 真实 TTF/OTF/TTC 文件；截图文字不是字体文件，也不能反解完整字库 |

## 易混淆规则

- 按钮/页签：查事件与选中关系，执行动作归按钮，切换内容归页签；同一控件兼有两种作用时按主要职责归类，次要用途写 tags。
- 轨道/进度槽：查关联子部件及状态变化，移动柄对应轨道，数值填充对应进度槽。单张截图无功能依据时向用户询问。
- 滑块/填充/端帽：看变化方式，位置变化的是柄，显露长度变化的是填充；固定端帽跟随所属部件，不机械拆成滑块。
- 窗口框/头像框/道具格：查所包围的内容和绑定对象；共享框按本次主要用途归类，其他用途写 tags，已有已确认公共资源身份优先。
- 底板/控件填充：页面连续底纹归底板，按钮或道具格自己的填充跟随控件；不可分部件按完整职责归一类，不为凑分类切碎。
- 装饰/图标：承担功能或状态语义的符号归图标，纯美术点缀归装饰；关闭按钮本体归按钮，需独立复用的关闭符号才单独归图标。
- 字体/文字图片：真字体依据文件验证；烘焙字样不能冒充字体，若是固定品牌标记需按实际职责判断，无法确定时询问。

## 无法明确分类时必须询问

先读现有原图、规格与功能依据；仍无法明确归属时，必须询问用户，即使该歧义暂不影响像素裁切也要询问。一次集中列出不明确项，给出原图位置/编号、可能类别、各自理由和缺失的功能信息。问题例如：“区域 B 点击后执行动作，还是切换内容？前者属于按钮，后者属于页签。”

待回答项标记 pending，暂停该项的提取、生成、登记和打包。不得把推荐选项、用户未回复、等待超时或外观猜测当作定类。其他明确素材可独立继续；不要以省事为由把未知部件归入装饰。收到回答后记录真实答复的位置/版本及理由，改为 resolved；已明确且仍适用的用户结论沿用，不重复询问。

## 分类依据的数据契约

在生产 task.assets、分层 plan.regions、报告 regions 和 Manifest.assets 使用相同 classification 对象。Schema 见 classification.schema.json。新定类的 UI 必须填写记录；历史无记录数据允许读取，但新打包前必须补齐，不能捏造旧证据。

```json
{
  "ui_type": "tab",
  "classification": {
    "status": "resolved",
    "role": "切换背包与装备内容",
    "basis": "功能说明规定同组互斥选择，选中项控制内容区",
    "evidence": ["功能说明.md：导航行为", "目标图 SHA-256 与区域 B"]
  }
}
```

role 为本次用途，basis 为判定理由，evidence 是可定位的原图/规格/绑定/真实用户答复引用。pending 额外填写 candidates（至少两个类别代码）与 question；它表示需要提问，不是脚本会自动发送问题。Codex 负责向用户展示区域和询问。无需编造概率或置信分数。

生产计划写入 classification；layers.py 从区域计划保存同样对象及 ui_type/category 到 report.json。提取导入时使用 production.py import --layer-report <report.json>，区域 id 与资产 id 对应；核对返回 PNG 哈希、类型和依据与生产计划一致后登记，attach 传到 Manifest，asset_package.prepare 传到标准清单。报告 SHA-256 在候选记录中保存。已登记真实字体可按字体文件及文本引用自动建立明确依据，不把截图猜测当证据。

完整素材包仍平铺在 assets/，分类只在信息中记录。确认、后续入库和复用保持原流程，分类依据随包进入素材库记录。包的内容哈希包含 classification，确认后更改依据也会使批准失效。

脚本只证明记录完整、无 pending 及传递一致，不能证明分类语义正确；评审仍检查实际用途和拆分结果。
