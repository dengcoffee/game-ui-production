# 游戏 UI 素材生产

这是一个总控 Skill。用户用自然语言指定系统和反馈；Codex 负责项目发现、计划、提示词、数据文件、工具调用及检查，不把 JSON 或命令链交给用户编制。网页只负责展示、对照和导出，生成由 Codex 的图像工具执行。

先读取项目 AGENTS.md、当前有效交付索引、整体 UI 设计、生产规范、Art Bible 和系统稿。遵守任务范围和已确认设计；参考工程的待办不自动成为当前任务。全局工具不含项目名称、画风、分辨率或路径，项目数据独立配置。

## 读取方式

- 首次配置或组装：读 [数据契约与合成](references/workflow.md)。
- 生产、候选管理、确认、冻结和清理：读 [生产操作](references/production.md)。
- 引擎接入或专项检查：读 [Godot 4 接入](references/godot.md)。

脚本位于本 Skill 的 scripts/，Python 3.11+ 及 requirements.txt 中依赖。先检查现有运行时，必要时创建独立环境。不要假定当前工作目录就是 Skill 目录。所有新产物写入独立候选版本，拒绝覆盖旧资源；未知能力直接说明限制。

## 执行流程

1. **发现与方向**：用 production.py discover 只读盘点，读取当前工作区的设计、生产规范、项目配置和布局记录。新项目先集中明确一次方向。
2. **参考身份核对**：已有目标效果图时，制作前查看用户本次指定的原图，核对路径或附件身份、SHA-256、实际像素尺寸、页面、状态、版本及确认范围，并记录到现有参考/规格记录。工作区已有明确匹配记录可沿用；不能仅凭文件名、同分辨率或旧索引选图。哈希不同先核对实际画面及编码差异；无法确定目标或与现行设计冲突时，先请用户明确，不擅自换参考或改版。局部裁切另记原图身份与裁切坐标，原图不变；区分公共母版、页面专属层与范围外内容。新设计没有既有目标图时明确标为方向探索，按方向确认流程建立参考，不虚构已确认效果图。
3. **尺寸基线确认**：初始化、系统计划和任何效果图、素材或样板制作前，明确游戏内容区的逻辑宽高、实际窗口大小及缩放/留边规则，以及本次 UI 主面板、弹窗和子窗口的目标宽高、位置或锚点；独立素材区分实际显示尺寸、可见主体尺寸与透明画布/效果留边。当前工作区已有明确且适用于本次任务的尺寸记录时，注明来源并沿用，不重复要求用户确认；缺少记录或必需尺寸未明确时，集中列出缺项，请用户确认后再进行依赖这些尺寸的制作，不自行猜测。记录冲突且现有权威或最新明确确认无法消解时，请用户确认冲突项。将基线写入现有项目设计/规格，并使 rules.logical_canvas、Manifest.canvas、布局 rect 与素材 display_size 一致；不新增竞争索引，不把参考图片像素大小当作已确认尺寸。尺寸明确后，已有项目用 adopt 映射现有目录与权威索引，不搬迁、不覆盖；新项目用 init 写候选 Art Bible 与状态索引，再制作代表性面板、按钮状态、页签和字体样板。用户确认后才成为正式依据；技术夹具不是美术确认。
4. **系统计划**：自行从功能稿整理系统、页面、子窗口、状态、真实数据字段和共享母版。有参考图时，提取前按 [自动分层识别](references/production.md#自动分层识别) 查看实际画面并结合功能职责判断底图、覆盖层、独立控件和动态内容，先提供分层预览与理由；默认将连续底色/底纹保留为完整底图，不要求用户每次声明、不按矩形布局切碎。已有项目规格或用户明确分层要求优先，只有无法判断且影响提取结果的歧义才询问。优先复用资源 ID 和公共几何，页面只记录差异。用 plan 注入项目 Art Bible、规则、实际显示尺寸、允许修改范围和重试预算。人物、内容 ICON、地图和背景默认引用或占位；生产需项目白名单及明确任务授权同时成立。
5. **素材生产**：优先已确认独立资源，其次明确范围提取/参考编辑，再生成缺项。按组装职责分离底图与覆盖层：公共底色/底纹由底图承担，页面边框、装饰、阴影、光晕及状态效果作为可叠加的独立 RGBA 素材；按钮等控件默认保留自身填充、边框与固定效果的完整美术，不只提取边框，具体按生产操作的自动分层识别规则处理。仅将需独立复用、切换或动画的部分分层，不强拆不可分的同一美术部件。覆盖层无关区域透明，实体框线按参考保留不透明度，阴影和光效保留连续半透明过渡，不夹带截图底色、头像或可变文字。矩形裁切及整页/局部截图只能作为参考中间产物，未完成分层去底不能登记为正式组件；PNG 文件格式或存在 Alpha 通道不等于已正确分层。仅有合成效果图时，不声称能精确反解原始透明图层；去底无法保留效果时，按参考编辑或重新制作独立覆盖层，如实标记来源。提取前将头像本体与头像框分为不同资源职责：头像框及其边缘装饰属于 UI 素材，只提取框与装饰，头像显示区域保持透明，不得夹带人物像素；头像本体属于内容资源，本轮 UI 提取不提取头像，仅引用既有资源或占位。不得将头像与头像框一起裁切后作为头像框交付；无法干净分离时，记录分离限制，按已确认参考单独制作框体，不声称已提取被头像遮挡的部分。确定性裁切或已提供蒙版使用 assets.py；不能声称补回遮挡。需要 AI 时 inspect 当前工具能力，prepare-provider 生成参数和尝试票据，在 Codex 调用真实图像工具；参考编辑先查看本地目标。将返回 PNG 用 import 登记来源、许可、哈希、透明和 bounds，用 attach 写新的 Manifest。失败登记 provider-failure，预算耗尽停止同方案重试；可使用受控外部 PNG 导入。禁止隐式调用其他 API、请求密钥或宣称像素锁定。
6. **素材与视觉检查**：运行 quality、inspect 和 build。文字用真实字体和数据绑定，不烘焙进美术；纹理、边缘、装饰、阴影和光效由图片承担。逐页逐状态查看 PNG 和工作台，差异只在本轮 UI 责任范围计算。检查缺字、Alpha、主体尺寸、显示精度、效果完整性和状态几何；覆盖层须在棋盘格及目标底图上分别查看，再按实际层序组装，检查矩形色块、重复底纹、接缝、去底色边及阴影/光效截断，不能只检查单张切片。数值不能自动批准美术。
7. **逐部件视觉匹配**：复用前和实际组装后，对照已核对身份的参考，逐项查看同一显示尺寸下的窗口、标题区、导航、按钮、分隔线、角饰与各状态，核对轮廓、主体比例、位置/锚点、材质、颜色、文字层级、图标造型、阴影及光效完整性。分别记录来源、技术检查、视觉差异和返修结果；同名、同职责或技术通过不能证明可复用。明确哪些层属于公共母版、哪些属于页面内容，不随内容移除公共装饰；真实裁切提取、参考编辑、重新生成和旧资源复用如实区分。用同画布、同状态的并排、叠加和局部对照验证当前责任范围，排除已声明的范围外内容。明显轮廓/材质/颜色失配、装饰缺失或未经授权的结构变化必须继续返修；仅当这些明显偏差已消除、剩余差异较小且逐项说明时，才提交还原评审。像素差数值和技术门禁不能单独判定差异较小。
8. **返修与压力测试**：根据逐部件对照及用户截图和版本身份定位素材/几何/字体/合成/引擎/交互根因。素材不匹配就返修或重制，布局不匹配就修组装，范围内缺项就补齐；每次返修后重建并重新逐部件核对，不把明显偏差转为“待用户确认”后结束。共享资源先查引用者；局部修改使用 build --previous 和 --pages 重建影响范围，最终交付须完整重建。用 stress 构造空态、长文本、最大列表、极端数值及缺字。不要改参考目标、临时偏移或遮罩掩盖失配。
9. **确认与冻结**：只有用户明确确认确切版本才记录 approve 的 actor、statement 和真实证据；不得自行编造确认。它核对完整页面/状态及当前哈希，freeze 保存便携资源、布局、Art Bible、证据和版本。测试批准必须在隔离项目标记 test_fixture/test_only，不能进入生产工程。
10. **引擎接入**：视觉冻结后用 godot_export.py 生成独立图层、字体、状态、输入区域、动画、滚动和实时数据组件。先在隔离工程用 engine_verify.py 做实际引擎检查及截图，再映射到现有 UI owner。业务事件和数据仍由游戏负责，未绑定字段明确列出。引擎截图单独检查字体差异并由用户试玩，技术通过不等于 engine_verified。
11. **维护与收尾**：维护项目 status_source 这一处当前权威，记录 draft/candidate/approved_reference/assets_verified/visual_approved/engine_verified 的证据与版本。自带格式使用 sync-status；已有 Markdown/自定义索引按其格式就地维护，替换前保留有限恢复依据，不新增竞争索引。更新状态后重新构建后续候选；冻结包保持不变。规范修改合并进现行条款，不追加互相冲突的补丁。clean-plan 检查候选引用，clean 只可恢复归档已登记旧候选，restore 可恢复；当前有效资产和最新候选受保护。

## 交付与停止条件

交付简短说明、可打开的对照入口、实际素材/布局、检查结果、精确版本和明确待决项。用户只需审核关键方向及最终视觉，不逐项维护工具。

确定性错误可修正源头；美术重试遵守预算。工具无法保证语义分割、被遮挡重建、AI 像素锁定或不同引擎字体逐像素一致，明确采用蒙版/外部候选/专项截图等可验证路径。未授权的引擎、任意混合模式或游戏业务绑定不猜测。预算耗尽或工具能力不足且仍有明显美术偏差时，报告未完成项、证据及可行后续路径，不称为可评审或还原完成，也不变更请求身份绕过预算。达到逐部件视觉匹配的评审条件但没有用户视觉批准时，交付真实候选并等待该必要验收，不伪造冻结和接入状态。
